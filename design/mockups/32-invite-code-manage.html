前端由 authStore.isAdmin 控制菜单渲染 + meta.requiresAdmin 路由守卫； 后端由 @RequireRole({ADMIN, SUPER_ADMIN}) 兜底，两侧任一缺失都不算完成。
「管理员角色码」是提权口子，收口到超级管理员：凡是 grant_role = ADMIN 的码， 其生成、启用/禁用、删除一律只认 SUPER_ADMIN；普通管理员在列表里看不到这些入口， 绕过前端直调接口会被后端以 95203 拦截（@RequireRole 只能表达接口级权限， 细粒度校验必须写在 Service 里）。

实现要点

  • 路由 /admin/invite-codes → views/admin/InviteCodeList.vue，meta: { requiresAdmin: true }。
  • 侧边栏「管理」分组新增 { label: '邀请码', key: '/admin/invite-codes', icon: TicketOutline }；MENU_TITLES 同步加映射。
  • 状态为计算态（后端由 status / expireAt / usedCount / maxUses 实时算），不落库、无定时任务。
  • 邀请码存储为 12 位大写无分隔明文，展示层每 4 位插 -；复制时复制不带连字符的原始值。
  • 「使用次数」列 usedCount / maxUses，用尽时数字用 info 色强调。
  • grant_role = ADMIN 的码：角色标签 warning 高亮，创建时备注必填，默认一次性； 生成与启停/删除均限超级管理员（95203），前端对非超管隐藏入口，后端独立校验。
  • 删除仅超管可见且仅 usedCount === 0；已使用的码只能禁用，保证审计链完整。
  • 「禁用 / 删除」均走 useConfirm() / confirmDanger()，与全站交互一致。
  • 统计数据随列表接口的 summary 字段一并返回，不额外请求。
